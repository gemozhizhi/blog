## 为什么要写这篇

这是一篇**示例文章**，作用有两个：

1. 让你老公照着这个格式写第一篇，不用现学 Markdown 语法
2. 让你能看到博客最终长什么样

写完这篇后，直接复制这个文件改名就行。

## 技术选型

我们选的是 **VitePress**：

| 维度 | VitePress | Astro | Hugo | Hexo |
|---|---|---|---|---|
| 上手难度 | 低 | 中 | 低 | 低 |
| 代码高亮 | 内置 | 需插件 | 需插件 | 需插件 |
| 本地搜索 | 内置 | 需插件 | 需插件 | 需插件 |
| 构建速度 | 快 | 快 | 最快 | 中 |
| 灵活性 | 高 | 最高 | 中 | 中 |

技术博客的核心需求是「写代码时不被打断」——VitePress 把这些都做进主题里了，不用自己配。

## 目录结构

```
blog/
├── docs/
│   ├── .vitepress/
│   │   ├── config.js       # 站点主配置
│   │   └── site.config.js  # 站点信息（改名字改这里）
│   ├── public/             # 静态资源（头像、favicon）
│   ├── posts/              # 文章放这里
│   ├── guide/              # 指南类页面
│   ├── index.md            # 首页
│   ├── archive.md          # 归档页
│   ├── tags.md             # 标签页
│   └── about.md            # 关于页
└── package.json
```

## 写一篇文章

新建 `docs/posts/my-first-post.md`：

```markdown
---
title: 我的第一篇文章
tags: ['教程']
date: 2026-11-11
---

正文内容，支持 **Markdown**。

- 列表
- 表格
- 代码块
```

就这么多。frontmatter 是文章的头部信息，`title` 必填。

## 本地预览

```bash
npm run docs:dev
```

浏览器打开 `http://localhost:5173`，改文件会自动热更新。

## 发布

```bash
npm run docs:build   # 构建
git add .
git commit -m "新增文章"
git push             # Cloudflare Pages 自动构建上线
```

## 一个小技巧

文章末尾可以加个分发引导，把读者引到知乎等平台。**但不要在正文里放裸链接**——2026 年知乎对外链审核很严，正文塞链接的回答折叠率超过 70%。

安全做法是放在个人简介栏，或者像这样自然地提一句：

::: tip 延伸阅读
关于这个问题的完整排查思路，我写过一篇更详细的文章，在知乎专栏和掘金同步更新。
:::

## 小结

- 一篇文章 = 一个 `.md` 文件
- 改完 `git push` 就上线
- 其余时间用来写内容，而不是折腾站点
