## 写之前

**先有一篇想写的东西，再动手。** 技术博客最容易死在"想写个系列但不知道写哪篇"。

判断标准很简单：如果你最近工作中遇到一个问题，查了半小时以上资料才搞明白——那它就值得一篇。

## 文件放哪

```
docs/posts/文章名.md
```

文件名用英文短横线，比如 `2026-11-11-vitepress-deploy.md`。

## Frontmatter

每篇文章开头必须有这一段：

```yaml
---
title: 文章标题
tags: ['标签1', '标签2']
date: 2026-11-11
---
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 显示在文章标题、归档页、搜索结果 |
| `tags` | 否 | 用于分类，建议 1-3 个 |
| `date` | 否 | 归档页排序用 |

## 推荐的文章结构

```markdown
## 背景
为什么要做这件事，遇到了什么问题

## 思路
解决方案的推导过程，这部分最重要

## 实现
代码，带完整上下文和版本号

## 踩坑
遇到的问题、报错信息、怎么定位的

## 小结
一句话总结 + 什么情况下不适用
```

「踩坑」这节是技术博客和文档的区别。有踩坑记录的博客，读者才愿意收藏。

## 代码块

````markdown
```ts
interface Config {
  name: string
  version: string
}
```
````

写代码一定标语言，高亮才生效。需要展示 diff：

````markdown
```diff
- const port = 3000
+ const port = process.env.PORT ?? 3000
```
````

## 写作时的几个提醒

- **标题写成问题或结论**，别写成"关于 XXX 的思考"这种没有信息量的
- **开头别铺垫**，直接进入问题，读者很忙
- **代码要能跑**，注明版本和依赖，缺一步就是坑
- **图用 SVG 或截图**，别用压缩过度的 JPG

## 发布流程

```bash
npm run docs:dev      # 本地预览
npm run docs:build    # 构建检查，有报错会在这里暴露
git add . && git commit -m "描述"
git push
```

推上去后 Cloudflare Pages 会自动构建，一般一两分钟生效。

## 分发到其他平台

写完博客文章后，同步到知乎 / 掘金 / CSDN。但**不要在正文塞裸链接**。

安全做法：
1. 知乎个人简介栏填博客网址
2. 知乎回答里把内容讲透，链接放在专栏或简介
3. 掘金/CSDN 直接同步全文，文末可以提一句「原文在 xxx.com」

::: warning 亲身教训级别的提醒
知乎 2025-2026 年对外链管控很严。实测带外链的回答折叠率超过 70%，折叠后申诉通过率不到 10%。回答质量越高、越少提链接，账号权重涨得越快。
:::
